# 个人职业发展与副业规划

> 本文记录个人职业发展和副业方向的阶段性思考，后续根据实际工作、能力积累和市场反馈持续更新。
>
> 当前版本：2026-08-24

## 一、当前基本判断

目前的工作条件：

- 央企总行直属机构正式员工。
- 甲方为总行，第一份劳动合同期限较长。
- 正常绩效下，短期内不存在明显的合同续签风险。
- 当前主要关注 AI 对研发岗位的影响，以及个人如何提前升级能力。

核心判断：

> 主业不应只追求“写更多代码”，而应逐步成为能借助 AI 交付可靠业务系统的人；副业不应急于追求规模，而应围绕公开能力和真实用户小步验证。

## 二、主业发展方向

推荐的能力组合：

```text
银行核心业务
  + 后端与系统架构
  + AI 辅助研发
  + 数据安全与合规
  + 生产稳定性和项目责任
```

AI 会首先减少低复杂度、重复性的编码工作，但不会马上消除复杂系统中的业务判断、架构设计、风险控制和生产责任。

因此职业目标应从：

```text
负责把代码写出来
```

升级为：

```text
负责把需求变成可靠、可验证、可上线、可维护的系统
```

## 三、可选择的职业路线

### 3.1 银行技术专家路线

重点积累：

- 支付、账户、清算、风控、数据等核心业务知识。
- 分布式系统、数据库、消息队列和服务治理。
- 系统稳定性、监控、故障处理和应急响应。
- 数据安全、权限、审计和监管要求。

这条路线的优势是业务壁垒和组织需求较稳定，适合长期深耕银行技术体系。

### 3.2 AI 工程路线

重点积累：

- 大模型 API、结构化输出和模型路由。
- Agent、工具调用、MCP、RAG 和向量检索。
- 文档、数据库、代码库和企业系统的 AI 接入。
- Prompt、Skills、评测、日志、权限和沙箱。
- 模型应用的成本、延迟、可靠性和安全治理。

目标不是只会调用聊天接口，而是能把 AI 做成可测试、可审计、可维护的业务系统组件。

### 3.3 业务技术复合路线

重点积累：

- 把业务需求翻译成技术方案。
- 识别真正值得自动化的流程。
- 设计系统边界、数据流和验收标准。
- 协调产品、业务、开发、测试和运维。
- 使用 AI 提高整个团队的交付效率。

这条路线对单纯编码的依赖较低，但要求更强的沟通、判断和责任承担能力。

## 四、未来 12 个月计划

### 4.1 0～3 个月：建立 AI 工作习惯

- 用 Codex 完成真实项目中的阅读、修改、测试和调试。
- 整理项目规则、常用命令、测试流程和文档规范。
- 总结适合自己的提示词、Skills 和代码审查清单。
- 学习 Agent、工具调用、上下文、权限和 MCP 的基本原理。
- 记录 AI 实际节省的时间，以及它经常犯错的场景。

阶段成果应是：能够稳定地让 AI 参与开发闭环，而不是只生成代码片段。

### 4.2 3～6 个月：做出可展示的 AI 工程项目

可以选择一个公开数据或个人项目，完成以下能力中的一部分：

- 数据检索和问答。
- 文档自动整理和报告生成。
- 代码库分析、测试生成或日志诊断。
- 数据库查询和结构化结果输出。
- 定时任务、消息通知和自动化流程。

项目必须具备：

- 明确的输入和输出。
- 可重复的运行方式。
- 基本测试和错误处理。
- 日志和成本记录。
- 不依赖单位内部数据或代码。

### 4.3 6～12 个月：形成个人技术标签

从以下方向中选择一个作为主要标签：

- 银行核心业务与系统稳定性。
- AI 辅助研发和企业自动化。
- 金融数据工程和分析工具。
- 老系统改造、迁移和平台整合。

阶段目标不是学习尽可能多的工具，而是形成“某类问题可以找我解决”的能力。

## 五、Codex 在职业规划中的位置

Codex 应作为日常研发效率工具，而不是单纯的代码生成器。建议逐步让它参与：

```text
需求分析
  -> 代码搜索
  -> 方案设计
  -> 多文件修改
  -> 测试和构建
  -> 报错修复
  -> Git diff 检查
  -> 文档和变更说明
```

同时要保留人工判断能力，特别是：

- 数据库和事务边界。
- 权限和敏感数据处理。
- 金融业务规则。
- 生产环境风险。
- 性能和故障恢复。
- 代码是否真正符合项目长期维护要求。

## 六、副业方向

### 6.1 AI 自动化工具

面向个人或小团队提供轻量工具，例如：

- 文件、PDF、Excel 和报告自动处理。
- 日志分析和故障摘要。
- 研发周报和变更说明生成。
- 数据清洗、查询和可视化。
- 小型团队的内部流程自动化。

优点是技术积累与主业相关，容易从小范围验证；缺点是需要找到明确的付费场景。

### 6.2 金融数据工具

可以围绕公开数据和合规边界发展：

- ETF 或行业数据看板。
- 行情数据整理和分析工具。
- 个人投资记录与复盘工具。
- 数据接口、指标计算和报告生成。

重点是工具和数据分析，不要轻易进入荐股、收费投顾或承诺收益的方向。

### 6.3 技术内容和知识产品

可以将学习和实践整理成：

- AI 辅助研发教程。
- Python、后端和数据库实践文章。
- Agent、MCP 和企业自动化案例。
- 面向初学者的项目文档和学习材料。
- 可复用的脚本、模板和 Skills。

这条路线前期收益慢，但可以积累公开作品、个人影响力和潜在客户。

### 6.4 小型 SaaS

不建议一开始做大型平台。优先选择一个具体问题，用 1～3 个月做出最小可用版本，然后观察是否有人持续使用或愿意付费。

验证顺序：

```text
找到具体用户
  -> 确认真实痛点
  -> 手工或半自动交付
  -> 获得第一批反馈
  -> 再决定是否产品化
```

## 七、副业边界和风险控制

因为任职于银行或央企体系，副业必须优先确认单位制度和合规要求。至少遵守：

- 不使用单位内部代码、数据、账号、设备或未公开资料。
- 不在工作时间处理个人业务。
- 不把单位业务经验包装成单位官方服务。
- 不接触可能造成利益冲突的客户或项目。
- 不泄露客户、交易、员工或内部系统信息。
- 不使用单位身份为副业背书。
- 涉及证券、投资建议、收费咨询时，先确认法律和监管边界。
- 需要时向单位人力、纪检、合规或法务部门确认兼职规定。

副业选择标准：

```text
不违反单位规定
  + 不依赖内部资源
  + 能积累公开作品
  + 可以逐步自动化
  + 有真实用户愿意付费
```

## 八、不建议当前投入的方向

- 只因为热门就同时部署 Hermes、OpenClaw 等复杂系统。
- 没有用户验证就做大型 AI 平台。
- 纯搬运 AI 新闻和产品宣传内容。
- 高风险投资、荐股或收益承诺。
- 只学习工具名称，不做完整项目。
- 过度依赖 AI 生成代码，忽略测试、安全和业务理解。

## 九、阶段性决策框架

每个季度复盘以下问题：

1. AI 是否让我的实际交付速度和质量提高？
2. 我是否掌握了一个更深的银行业务领域？
3. 我是否能独立负责一个系统或关键模块？
4. 我是否有可公开展示、但不涉及单位机密的作品？
5. 副业是否有真实用户，而不是只有自己的兴趣？
6. 是否违反了单位关于兼职、利益冲突和信息安全的规定？

## 十、当前建议

近期最合理的组合是：

```text
主业：成为懂银行业务、系统架构和 AI 工程的复合型研发
工具：把 Codex 深度融入日常研发流程
副业：围绕 AI 自动化或金融数据做一个小产品验证
原则：先积累能力和用户，再考虑规模化
```

当前不需要因为 AI 热潮立刻改变职业或购买服务器。先用现有电脑、Codex 和个人项目完成小规模验证，等出现明确的常驻、定时或远程自动化需求后，再考虑 Hermes、OpenClaw 或云服务器。

## 十一、后续继续思考的问题

- 当前最值得深挖的银行业务领域是什么？
- 自己更适合技术专家、AI 工程还是业务技术复合路线？
- 个人金融数据项目的目标用户是谁？
- 哪个副业方向能在不触碰合规边界的情况下最快获得反馈？
- 如何把 Codex 使用经验沉淀成可复用的项目流程和 Skills？
- 未来一年应该用什么具体成果证明自己的能力升级？
