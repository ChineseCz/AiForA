## 二、部署流程

### 2.1 日常部署（代码更新）

```bash
# 1. SSH 登录
ssh ubuntu@124.222.169.60

# 2. 进入项目目录
cd /data/app

# 3. 拉取最新代码
git pull --ff-only origin dev

# 4. 检查配置并重建应用服务
cd backend
docker compose config -q
docker compose up -d --build api worker beat browser-worker frontend

# 5. 执行数据库迁移
docker compose exec -T api alembic upgrade head

# 6. API 重建后重新创建 frontend，让 Nginx 重新解析 API 地址
docker compose up -d --force-recreate frontend

# 7. 检查服务状态
docker compose ps

# 8. 验证服务
curl --fail http://localhost:8090/health
curl --fail http://localhost:8090/
```

> 不要在日常部署中执行 `docker compose down -v` 或 `docker volume prune`，避免删除 PostgreSQL、Redis 数据卷。

### 2.2 代码热更新（后端 API 修改）

```bash
ssh ubuntu@124.222.169.60
cd /data/app

# 拉取代码
git fetch origin
git pull --ff-only origin dev

# 只重建 API 容器（约 30 秒）
cd backend
docker compose up -d --build api

# 如果修改了浏览器任务代码，还必须重建服务器端 browser-worker
docker compose up -d --build --force-recreate browser-worker

# 验证
docker compose logs -f api
```

### 2.3 前端更新

```bash
ssh ubuntu@124.222.169.60
cd /data/app
git pull --ff-only origin dev

cd backend
docker compose up -d --build frontend

# 如果 API 容器刚刚重建，再执行一次 frontend 重建
docker compose up -d --force-recreate frontend

# 验证（浏览器访问 http://124.222.169.60）
```

### 2.4 数据库迁移

```bash
ssh ubuntu@124.222.169.60
cd /data/app/backend

# 查看待执行的迁移
docker compose exec api alembic current
docker compose exec api alembic history

# 执行迁移
docker compose exec api alembic upgrade head

# 回滚（谨慎）
docker compose exec api alembic downgrade -1
```

## 三、日常运维

### 3.1 查看日志

```bash
# 实时日志
docker compose logs -f api
docker compose logs -f worker
docker compose logs -f beat
docker compose logs -f browser-worker

# 最近 100 行
docker compose logs --tail=100 api
docker compose logs --tail=100 browser-worker

# 所有服务
docker compose logs -f
```

### 3.2 重启服务

```bash
# 重启单个服务
docker compose restart api

# 重启所有服务
docker compose restart

# 完全停止后启动（重新加载配置）
docker compose down
docker compose up -d
```

### 3.3 进入容器调试

```bash
# 进入 API 容器
docker compose exec api bash

# 进入 PostgreSQL
docker compose exec postgres psql -U postgres -d natapp

# 进入 Redis
docker compose exec redis redis-cli
```

### 3.4 清理磁盘空间

```bash
# 清理未使用的镜像
docker image prune -a -f

# 清理停止的容器
docker container prune -f

# 清理未使用的卷（谨慎）
docker volume prune -f

# 查看磁盘占用
docker system df
```

## 四、常见问题排查

### 4.1 容器启动失败

```bash
# 查看容器状态
docker compose ps

# 查看失败原因
docker compose logs api

# 常见原因：
# - 端口被占用：lsof -i :8088
# - 环境变量缺失：检查 .env 文件
# - 数据库未就绪：等待 postgres 容器启动完成
```

### 4.2 API 返回 502/503

```bash
# 检查 API 容器是否运行
docker compose ps api

# 检查 Nginx 反向代理
sudo nginx -t
sudo systemctl status nginx

# 检查容器网络
docker network ls
docker network inspect backend_app-network
```

### 4.3 数据库连接失败

```bash
# 检查 PostgreSQL 状态
docker compose logs postgres

# 测试连接
docker compose exec api python -c "
from app.core.db import engine
with engine.connect() as conn:
    print('Database OK')
"

# 检查 PgBouncer
docker compose exec pgbouncer psql -h localhost -p 5432 -U postgres -d natapp
```

### 4.4 Celery 任务不执行

```bash
# 检查 worker 状态
docker compose logs worker

# 检查 beat 调度器
docker compose logs beat

# 检查服务器端 Playwright 浏览器 worker
docker compose logs --tail=200 browser-worker

# 进入 Redis 查看队列
docker compose exec redis redis-cli
> LLEN celery
> LRANGE celery 0 10

# 手动触发任务（测试用）
docker compose exec api python -c "
from app.workers.celery_app import app
app.send_task('app.workers.tasks.stock.sync_all_snapshots')
"
```

## 五、备份与恢复

### 5.1 数据库备份

```bash
# 自动备份（脚本已配置）
cd /data/app/backend
bash scripts/backup.sh

# 备份文件位置
ls -lh /data/backups/
```

### 5.2 数据库恢复

```bash
# 从备份恢复（谨慎操作）
cd /data/app/backend

# 停止服务
docker compose stop api worker beat

# 恢复数据
gunzip < /data/backups/backup-YYYYMMDD-HHMMSS.sql.gz | \
  docker compose exec -T postgres psql -U postgres -d natapp

# 重启服务
docker compose start api worker beat
```

### 5.3 配置文件备份

```bash
# 备份 .env 和 docker-compose.yml
cd /data/app/backend
tar czf ~/config-backup-$(date +%Y%m%d).tar.gz .env docker-compose.yml

# 下载到本地
scp ubuntu@124.222.169.60:~/config-backup-*.tar.gz ./
```

- [ ] SSL 证书是否即将过期（如已配置 HTTPS）

### 6.2 安全加固建议

```bash
# 1. 修改 SSH 端口（可选）
sudo nano /etc/ssh/sshd_config
# Port 22 → Port 2222
sudo systemctl restart sshd

# 2. 配置防火墙
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 2222/tcp  # 如果修改了 SSH 端口
sudo ufw enable

# 3. 禁用密码登录（仅允许 SSH 密钥）
sudo nano /etc/ssh/sshd_config
# PasswordAuthentication no
sudo systemctl restart sshd

# 4. 定期更新系统
sudo apt update && sudo apt upgrade -y
```
