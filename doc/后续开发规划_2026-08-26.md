## 一、截至 8 月 26 日已完成内容

### 1. 服务化系统

- 前端使用 React、TypeScript、Vite 和 Ant Design；
- 后端使用 FastAPI；
- 正式数据库使用 Docker PostgreSQL；
- Redis 用于缓存和 Celery 队列；
- Nginx 负责静态前端和 API 反向代理；
- Alembic 数据库迁移已推进到 `0020`；
- 服务器生产目录为 `/data/app`，生产分支为 `dev`。

### 2. APK 封装

- 使用 Capacitor 生成 Android WebView 外壳；
- APK 启动后访问 `http://124.222.169.60/`；
- React 页面和 FastAPI 接口仍运行在服务器；
- APK 只是 Android 应用入口和网页容器，不直接连接数据库；
- 服务器前端和后端更新时，通常不需要重新安装 APK；
- Android 工程和 APK 构建产物仅保留在本地，不提交 Git。

### 3. 8 月 26 日移动端与看板优化

- 看板大盘增加日线、周线、月线切换；
- 后端支持指数日线聚合为周线/月线，并重新计算 MA、MACD、KDJ；
- 修复小米手机状态栏与网页 Header 重叠，用户按钮恢复可点击；
- 增加首屏启动加载页，减少远程 WebView 初次加载时的白屏感；
- 修复 API 容器重建后 Nginx 缓存旧 Docker 内部 IP 导致的 502；
- 增加 `deploy_server.sh`，统一服务器拉取、构建、迁移和健康检查流程；
- 删除根目录一次性测试、补丁、检查和旧上传脚本；
- 清理数据库备份文件，避免大文件进入 Git 推送历史。

## 二、总体开发路线

建议按照以下顺序推进：

```text
HTTPS 与安全
      ↓
部署与服务稳定性
      ↓
数据同步和监控
      ↓
APK 正式版体验
      ↓
自选、提醒和个性化
      ↓
会员和盈利功能
```

先把基础设施和数据可靠性做好，再扩展用户功能，可以减少后续返工。

## 三、P0：正式上线基础能力

### 1. HTTPS

当前公网入口仍为：

```text
http://124.222.169.60/
```

正式公开使用前应改为域名 HTTPS：

```text
https://你的域名/
```

需要完成：

- 注册并解析域名；
- 按服务器和业务要求办理备案；
- 申请 HTTPS 证书；
- 配置 Nginx 443 端口；
- HTTP 自动跳转 HTTPS；
- 更新 APK 的远程地址；
- 关闭 Android HTTP 明文访问配置；
- 检查登录 Token、验证码和 API 请求是否全部走 HTTPS。

### 2. 稳定部署

服务器部署脚本已经加入项目：

```bash
cd /data/app
bash deploy_server.sh
```

后续还可以增加：

- 部署前自动备份数据库；
- 部署失败自动停止并保留旧容器；
- 部署后自动检查所有服务；
- 自动检查 Alembic 是否到 head；
- 输出部署版本和 Git commit；
- 部署日志保存到固定目录。

特别注意：

```bash
docker compose down -v
```

不能作为普通部署命令使用，因为它可能删除 PostgreSQL 和 Redis 数据卷。

### 3. Docker 网络稳定性

当前 API 容器重建后可能获得新的内部 IP，而前端 Nginx 可能短暂保留旧 IP，造成：

```text
502 Bad Gateway
connect() failed (111: Connection refused)
```

当前部署脚本通过重新创建 frontend 容器解决。后续可以进一步优化为：

- 使用更稳定的 Docker 服务发现方式；
- 让 Nginx 在请求阶段重新解析服务名；
- 将 API 和 frontend 放在明确的共享网络中；
- 将 502 自动检查加入部署脚本。

## 四、P1：数据质量和可观测性

### 1. 行情数据监控

当前数据库已经保存大量历史行情，但还需要让管理者能够快速知道数据是否正常：

- 最后一次股票行情同步时间；
- ETF 最后同步时间；
- 可转债最后同步时间；
- 各资产实际交易日数量；
- 缺失或异常标的数量；
- 同步成功数量和失败数量；
- 上游接口错误原因。

### 2. 回补失败清单

项目已有 `backfill_failures` 表和 `0020` migration。后续应在管理后台增加：

- 失败资产类型；
- 失败代码；
- 最后任务 ID；
- 最后错误信息；
- 更新时间；
- 单个重试按钮；
- 批量重试按钮；
- 成功后自动清除记录。

### 3. 任务状态展示

管理后台目前已有任务入口，后续可以补充：

- 当前运行状态；
- 开始时间和结束时间；
- 处理数量；
- 成功数量；
- 失败数量；
- 最近一次错误；
- 预计剩余时间。

目标是让日常运维尽量通过管理后台完成，减少必须登录服务器查看日志的情况。

## 五、P1：K 线和分析能力

### 1. 周线/月线完善

8 月 26 日已增加大盘周线/月线。后续继续检查：

- 跨月聚合；
- 跨年聚合；
- 节假日和非完整交易周；
- 周初、月初数据；
- 新上市指数或数据不足情况；
- 周线/月线缓存是否需要独立 TTL。

### 2. 详情页能力统一

逐步统一股票、ETF 和可转债详情页：

- 日/周/月 K 线；
- MA、MACD、KDJ；
- 买卖信号；
- 数据更新时间；
- 数据来源；
- 无数据和回补中提示；
- 实时行情刷新状态。

### 3. 回测能力

选股和模拟盘继续完善：

- 收益率；
- 最大回撤；
- 胜率；
- 交易次数；
- 交易明细；
- 手续费和滑点；
- 数据不足提示。

当前系统只用于信息整理和策略研究，不接入真实券商下单。

## 六、P1：APK 正式版

当前 APK 是 Debug 版本，适合内部测试。后续需要：

- 配置 Release 签名；
- 设置正式版本号；
- 替换正式图标和启动页；
- 配置 HTTPS 地址；
- 完善 Android 返回键；
- 增加网络断开和服务器异常提示；
- 测试小米、华为、OPPO、vivo 等常见设备；
- 生成 Release APK 或 AAB；
- 保存 keystore 和签名密码，不提交 Git。

建议 APK 文件命名为：

```text
xueqiu-insight-v1.0.0.apk
```

APK 下载文件放在服务器静态目录，不放进 Git：

```text
/data/app/frontend/public/downloads/
```

## 七、P2：用户功能

### 1. 自选系统

- 自选股票；
- 自选 ETF；
- 自选可转债；
- 自选分组；
- 分组排序；
- 实盘/模拟盘分离；
- 自选列表批量刷新。

### 2. 个性化设置

- 保存选股条件；
- 保存 K 线指标显示状态；
- 保存首页默认指数；
- 保存默认 K 线周期；
- 保存主题和移动端显示偏好。

### 3. 消息提醒

- 自选标的价格变化提醒；
- 买卖信号提醒；
- 大 V 新帖提醒；

- 数据同步异常提醒。

提醒功能需要结合 Web Push、短信、邮件或 Android 原生推送，建议先实现站内消息，再选择外部渠道。

## 八、P2：盈利和运营

### 1. 会员分级

可以考虑将功能分为：

- 游客：有限浏览和基础看板；
- 普通用户：登录、收藏、保存筛选条件；
- 会员用户：更长历史数据、更丰富 AI 分析和提醒；
- 管理员：数据同步、任务管理和系统配置。

具体权限应在后端控制，不能只依赖前端隐藏按钮。

### 2. 收费前置工作

正式收费前需要确认：

- 员工兼职和经营活动相关内部规定；
- 金融信息服务相关合规边界；
- 支付平台要求；
- 个人或企业主体选择；
- 发票和税务处理；
- 隐私政策和用户协议；
- 用户数据保护和删除机制。

项目内容应保持信息整理、数据展示和研究辅助定位，不直接提供个性化买卖建议或代客操作。

## 九、当前不建议优先做的事情

- 暂不接入真实券商交易；
- 暂不把数据库端口暴露到公网；
- 暂不把 APK 和数据库备份提交 Git；
- 暂不为了实现离线而重写全部前端；
- 暂不同时接入多个复杂支付渠道；
- 暂不在数据质量未稳定前大规模推广；
- 暂不依赖前端隐藏功能实现权限控制。

## 十、推荐的下一次开发任务

下一轮最适合先做：

1. 增加服务器部署后的自动版本和健康检查；
2. 完善管理后台数据同步状态和失败清单；
3. 增加 APK 网络异常和加载失败页面；
4. 检查大盘周线/月线在边界日期的聚合结果；
5. 规划域名、HTTPS 和正式 APK 地址；
6. 再开始自选股和站内提醒。

## 十一、阶段结论

截至 2026 年 8 月 26 日，项目已经具备：

- 服务器运行能力；
- PostgreSQL 持久化数据；
- FastAPI API 服务；
- React 移动端网页；
- Android WebView APK 入口；
- 基础部署自动化；
- 股票、ETF、可转债和大 V 内容分析能力。

项目下一阶段的核心目标不是单纯增加页面，而是将系统从“可以使用”推进到“稳定、安全、可监控、可持续运营”。
