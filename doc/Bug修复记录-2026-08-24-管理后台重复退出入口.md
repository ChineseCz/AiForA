# Bug 修复记录：管理后台重复显示退出登录

## 1. 问题描述

管理员进入管理后台后，页面标题区域和全局 Header 账号菜单中都显示了“退出登录”。两个入口执行的是同一个管理员 token 清理动作，造成界面重复，也容易让人误以为后台存在两套独立登录态。

## 2. 原因分析

- `frontend/src/App.tsx` 已在全局 Header 的账号菜单中提供管理员退出入口。
- `frontend/src/pages/Admin.tsx` 又单独引入 `useAuth`，在后台标题右侧重复渲染退出按钮。
- 管理员退出只需要清理管理员 token，并由全局账号菜单统一完成跳转和状态更新。

## 3. 修复内容

- 删除 `Admin.tsx` 中重复的“退出登录”按钮。
- 删除该页面不再使用的 `useAuth` 引入和 `logout` 解构。
- 管理后台标题保留为单独标题，退出操作统一使用全局 Header 账号菜单。
- 未修改管理员鉴权、token 清理和路由守卫逻辑。

## 4. 验证结果

- `npm run build`：通过。
- `docker compose up -d --build frontend`：通过，前端容器已重建并启动。
- `http://localhost:8090/`：返回 HTTP 200。
- `backend-frontend-1`：运行中，端口映射为 `8090:80`。
- 后端、PostgreSQL、Redis、worker、beat、browser-worker 等既有容器状态正常。

## 5. 手动验证步骤

1. 打开 `http://localhost:8090` 并以管理员身份登录。
2. 进入“管理后台”，确认页面标题右侧不再出现重复的“退出登录”按钮。
3. 点击右上角账号菜单中的退出入口。
4. 确认管理员 token 被清理，并跳转回登录页；再次访问管理后台时不能直接进入。

## 6. 影响范围

本次为前端管理后台展示修复，不涉及数据库迁移和后端接口变更。已有的邮箱登录、验证码和密码重置相关改动随当前功能分支一并整理合并到 `dev`。
