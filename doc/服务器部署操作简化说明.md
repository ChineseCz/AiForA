# 服务器部署操作简化说明

服务器：`ubuntu@124.222.169.60`

项目目录：`/data/app`

生产分支：`dev`

## 推荐部署方式

先登录服务器：

```bash
ssh ubuntu@124.222.169.60
```

然后执行项目根目录中的脚本：

```bash
cd /data/app
bash deploy_server.sh
```

脚本会依次完成：

1. 使用 `git pull --ff-only origin dev` 拉取最新代码；
2. 检查 Docker Compose 配置；
3. 构建并启动 `api`、`worker`、`beat`、`browser-worker`、`frontend`；
4. 执行 `alembic upgrade head`；
5. 重新创建 frontend，让 Nginx 重新解析 API 容器地址；
6. 检查容器状态、首页和健康接口。

脚本不会执行 `docker compose down -v`，不会主动删除 PostgreSQL 或 Redis 数据卷，也不会输出 `.env` 中的密钥。

## 手动部署命令

```bash
cd /data/app
git pull --ff-only origin dev
cd backend
docker compose config -q
docker compose up -d --build api worker beat browser-worker frontend
docker compose exec -T api alembic upgrade head
docker compose up -d --force-recreate frontend
docker compose ps
```

### 为什么必须重新构建 browser-worker

服务器上的 `browser-worker` 使用 Docker 镜像内的业务代码，没有挂载宿主机的 `./app`。因此：

- `git pull` 只更新服务器源码，不会更新已经存在的 Docker 镜像；
- 只执行 `docker compose restart browser-worker` 仍会运行旧镜像；
- 浏览器任务（雪球抓取、K 线回补等）代码变更后，必须执行：

```bash
cd /data/app/backend
docker compose up -d --build --force-recreate browser-worker
```

否则可能出现类似以下错误：

```text
TypeError: task_backfill() got an unexpected keyword argument 'asset_type'
```

## 查看日志

```bash
docker compose logs --tail=100 api
docker compose logs --tail=100 frontend
docker compose logs --tail=100 worker
docker compose logs --tail=100 beat
docker compose logs --tail=100 browser-worker
```

实时查看浏览器任务及回补进度：

```bash
docker compose logs -f browser-worker
```

如果 frontend 日志出现：

```text
connect() failed (111: Connection refused) while connecting to upstream
```

通常是 API 容器重建后 Nginx 仍缓存旧的 Docker 内部 IP。执行：

```bash
docker compose up -d --force-recreate frontend
```

## AI 中转站配置

AI 配置在服务器独立的 `backend/.env`，不会随 Git 自动更新。修改后执行：

```bash
cd /data/app/backend
docker compose up -d --force-recreate api worker beat browser-worker
docker compose up -d --force-recreate frontend
```

确认以下变量已填写，但不要把密钥提交到 Git：

```env
RELAY_API_KEY=...
RELAY_API_URL=...
RELAY_MODEL=...
```

## 数据库注意事项

生产数据库是 Docker PostgreSQL，数据保存在 Compose 的 `pgdata` volume 中。代码更新和 Alembic 只负责同步表结构，不会自动从本地 SQLite 同步业务数据。

禁止在正常部署时执行：

```bash
docker compose down -v
docker volume prune
```

这类命令可能删除数据库或 Redis 数据。

## APK 下载文件

APK 不进入 Git。将 APK 上传到服务器临时目录后，放入：

```text
/data/app/frontend/public/downloads/
```

例如：

```bash
sudo mkdir -p /data/app/frontend/public/downloads
sudo mv /tmp/xueqiu-insight-v1.0.0.apk /data/app/frontend/public/downloads/
```

重新构建 frontend 后，下载地址为：

```text
http://124.222.169.60/downloads/xueqiu-insight-v1.0.0.apk
```

## 重要区别

- 修改后端代码：重建 `api`，必要时同步重建 `frontend`；
- 修改前端代码：重建 `frontend`；
- 修改数据库结构：重建后执行 `alembic upgrade head`；
- 修改 `backend/.env`：强制重建读取环境变量的容器；
- 修改服务器 IP、APK 原生配置或图标：重新生成 APK；
- 修改服务器网页和 API 业务代码：通常不需要重新安装 APK。
