# 前后端架构与代码文件说明

## 1. 文档目的

本文用于帮助开发者理解当前雪球大V看板与 A 股选股系统的代码结构。重点说明：

- 浏览器请求如何经过前端、Nginx 和 FastAPI。
- PostgreSQL、Redis、Celery、worker 之间如何配合。
- 前端主要目录和代码文件分别负责什么。
- 后端 API、核心模块、模型、仓储、服务和任务文件分别负责什么。
- 修改代码时应该从哪一层开始查找。

本文描述的是当前 `dev` 分支的服务化架构。

## 2. 总体架构

```text
浏览器
  |
  v
React + Vite 前端（容器内 Nginx，宿主 8090）
  |
  |  页面请求 /api/*
  v
Nginx 同源反向代理
  |
  v
FastAPI API（容器内 8000，宿主 8088）
  |
  +--> PostgreSQL：业务数据、用户、行情、任务状态
  |
  +--> Redis：缓存、Celery 消息队列、接口限流
  |
  +--> Celery：把长任务交给后台 worker
          |
          +--> default：行情、财务、板块、指标
          +--> llm：AI 总结
          +--> browser：雪球抓取、K线回补、雪球板块
```

当前 Compose 服务包括：

| 服务 | 作用 | 宿主端口 |
|---|---|---:|
| `frontend` | Nginx 托管前端静态文件，并代理 `/api` | 8090 |
| `api` | FastAPI 接口服务 | 8088 |
| `postgres` | 主数据库 | 5433 |
| `redis` | 缓存和消息队列 | 6380 |
| `pgbouncer` | PostgreSQL 事务级连接池 | 6432 |
| `worker` | 消费普通 Celery 任务 | 无 |
| `beat` | 定时投递 Celery 任务 | 无 |
| `browser-worker` | 消费依赖浏览器登录态的任务 | 无 |

用户通常只需要访问：

```text
http://localhost:8090
```

### 2.1 `index.html`、`main.tsx` 和实际页面的关系

React 项目仍然需要一个 HTML 入口，但 `frontend/index.html` 通常只是应用外壳，不是业务页面本身。它主要提供 `root` 挂载点并加载前端启动脚本：

```html
<div id="root"></div>
<script type="module" src="/src/main.tsx"></script>
```

启动关系是：

```text
浏览器加载 index.html
  -> 找到 #root 空容器
  -> 加载 main.tsx 编译后的 JavaScript
  -> ReactDOM 将 App 挂载到 #root
  -> App 根据路由加载 pages/*.tsx
  -> 用户看到实际业务页面
```

因此，`index.html` 会参与页面启动，但看板、选股、股票详情和管理后台等实际内容主要由 React 的 TSX 组件生成。`index.html` 中的标题、图标和 viewport 配置仍然会影响浏览器标签页和页面基础行为。

## 3. 一次请求的完整路径

以打开选股页为例：

```text
1. 浏览器访问 /screener
2. React Router 加载 Screener 页面
3. 页面通过 TanStack Query 请求 /api/screen
4. Nginx 将 /api/screen 转发到 api:8000
5. FastAPI 检查访客/管理员/匿名访问权限
6. 后端优先查询 Redis 缓存
7. 缓存没有命中时查询 PostgreSQL 或执行选股服务
8. 后端返回 JSON
9. TanStack Query 缓存结果
10. React 根据数据渲染表格和图表
```

以管理员触发行情同步为例：

```text
1. 管理员点击前端按钮
2. 前端携带 admin JWT 请求 POST /api/stock/sync
3. FastAPI 验证管理员身份
4. API 创建 job_runs 记录并投递 Celery
5. API 立即返回“任务已启动”
6. worker 在后台执行同步
7. worker 持续更新 job_runs 状态和日志
8. 前端轮询 status 接口显示运行中、完成或失败
```

## 5. 后端代码说明

后端根目录：`backend/`

### 5.1 启动入口

| 文件 | 作用 |
|---|---|
| `app/main.py` | 创建 FastAPI 应用，注册中间件、公开路由、管理员路由、健康检查和指标接口。 |
| `app/__init__.py` | Python 包初始化，通常不承载业务逻辑。 |

## 6. 修改功能时如何定位代码

### 修改一个普通页面

```text
frontend/src/pages/具体页面.tsx
  -> frontend/src/api/hooks.ts
  -> frontend/src/api/types.ts
  -> backend/app/api/routers/public/*.py
  -> backend/app/services/*.py
  -> backend/app/repositories/*.py
```

### 修改管理员后台任务

```text
frontend/src/pages/Admin.tsx
  -> frontend/src/api/hooks.ts
  -> backend/app/api/routers/admin/jobs.py
  -> backend/app/workers/tasks/*.py
  -> backend/app/services/ingest.py 或具体业务 service
  -> backend/app/repositories/sync_data.py
```

### 修改登录和权限

```text
前端：VisitorLogin.tsx / auth.tsx / visitorAuth.tsx / api/client.ts
后端：public/user_auth.py / admin/auth.py / api/deps.py
基础：core/security.py / core/config.py
```

### 修改选股逻辑

```text
frontend/src/pages/Screener.tsx
  -> frontend/src/api/hooks.ts
  -> backend/app/api/routers/public/screen.py
  -> backend/app/services/screen_api.py
  -> backend/app/services/screening.py
  -> backend/app/services/indicators.py
  -> backend/app/models/indicator.py
```

### 修改行情或 K 线

```text
前端：StockDetail.tsx / Dashboard.tsx
后端：public/stocks.py / services/views.py
数据源：services/external/sina.py 或 eastmoney.py
存储：repositories/sync_data.py / models/stock_daily.py / models/bond_daily.py
回补：scrapers/kline.py / workers/tasks/browser.py
```

## 7. 修改时需要遵守的边界

1. 轻量读取使用异步数据库会话。
2. 选股、K线和大规模计算使用同步逻辑时，必须放到线程池，不能阻塞 FastAPI 事件循环。
3. 长任务通过 Celery 执行，API 只负责校验、投递和返回任务状态。
4. 抓取雪球的代码放在 browser 队列，不要在普通 API 中直接启动 Playwright。
5. 数据同步完成后要处理缓存版本失效，避免前端继续读取旧数据。
6. 修改数据库模型时，同时增加 Alembic migration，并验证 `alembic upgrade head`。
7. 修改接口返回字段时，同时检查前端 hooks、types 和页面使用处。
8. 修改管理员接口时，确认是否经过 `require_admin`，不要只依赖前端隐藏按钮。
9. 修改预计算指标逻辑时，要对比预计算结果和现算结果，避免选股结果不一致。
10. 修改前端跨路由状态时，注意 `live2d.ts`、`pageContext.ts` 和 `screenerState.ts` 使用的是模块级单例。

## 9. 总结

当前系统的职责分工可以概括为：

```text
React：页面、交互和前端缓存
Nginx：静态文件和同源代理
FastAPI：HTTP 接口、权限和请求编排
Service：业务规则和计算
Repository：数据库读写
PostgreSQL：持久化业务数据
Redis：缓存、队列和限流
Celery：后台任务
Playwright worker：雪球浏览器抓取和回补
```

遇到问题时，建议先判断它属于哪一层：页面展示、接口请求、权限校验、业务计算、数据库读写、缓存，还是异步任务。确定层次后，再沿着本文的调用链定位代码，通常比直接全局搜索业务词更快。
