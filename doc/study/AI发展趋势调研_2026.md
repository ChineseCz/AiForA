# AI 发展趋势调研（2026）

> 调研时间：2026-08-24
>
> 本文关注对研发工程师有实际影响的技术发展，不把产品宣传语直接等同于成熟能力。模型版本、价格和产品功能变化很快，本文重点记录相对稳定的行业方向。

## 一、先说结论

当前 AI 的主要变化，不是简单地把聊天模型变得“更会说话”，而是从：

```textj
一次性生成内容
```

逐渐转向：

```text
理解目标 -> 分解任务 -> 调用工具 -> 观察结果 -> 修正 -> 交付结果
```

因此未来一段时间最重要的竞争点大概率是：

1. 模型能否稳定完成长流程任务。
2. Agent 能否可靠使用工具、文件、浏览器、代码库和业务系统。
3. 是否有好的评测、权限控制、审计和回滚机制。
4. 同等能力下，推理速度和调用成本能否下降。
5. 模型能否进入真实工作流，而不是停留在演示页面。

## 二、推理模型成为主线

传统语言模型更像是根据上下文直接生成下一个答案。新一代模型越来越强调推理时计算（test-time compute）：面对复杂问题时，模型投入更多计算进行分解、检查和尝试。

这会带来两个变化：

- 简单问题可以使用快速、便宜的模型。
- 复杂问题可以使用更慢但更擅长规划和验证的模型。

实际系统因此会采用模型路由：

```text
简单分类/补全 -> 小模型或快速模型
复杂分析/代码重构 -> 推理模型
高风险操作 -> 推理模型 + 工具验证 + 人工确认
```

需要注意，推理时间变长不等于结果一定正确。模型仍可能错误理解需求、调用错误工具或在错误方向上进行很长的推理，所以外部测试和验证仍然重要。

## 三、Agent 从概念演示走向工作流

Agent 的核心不是一个新模型，而是：

```text
大模型 + 工具 + 状态 + 控制循环 + 权限
```

目前最有价值的 Agent 往往不是完全自主的“万能助手”，而是边界明确的工作流 Agent，例如：

- 代码库修改和测试 Agent
- 客服工单处理 Agent
- 数据分析和报告 Agent
- CI 失败分析 Agent
- 服务器巡检 Agent
- 文档检索和知识库 Agent

可靠的 Agent 通常采用有限权限、明确工具、结构化输出、步骤上限、测试验证和人工审批，而不是让模型拥有无限制的主机权限。

## 四、代码 Agent 从补全走向软件工程

AI 编程的重点已经从单行代码补全，逐步转向仓库级任务：

```text
需求 -> 搜索代码 -> 理解架构 -> 修改多文件 -> 运行测试 -> 修复 -> 生成变更说明
```

对研发工程师来说，最有价值的能力包括：

- 在大型代码库中定位相关模块
- 理解接口、数据库、前端和后台之间的关系
- 根据测试失败继续迭代
- 做代码审查和风险分析
- 处理迁移、重构和依赖升级
- 在隔离环境中运行构建、测试和部署检查

这也是 Codex 类工具的重点。未来开发者的工作不会消失，但工作重心会更多转向：

- 明确需求和验收标准
- 设计系统边界
- 判断架构和技术取舍
- 维护测试、监控和安全约束
- 审查 AI 生成的改动

## 五、工具协议和 Agent 互操作性

如果每个 Agent 都用自己的工具接入方式，开发成本会很高。因此行业正在形成两类基础设施方向：

### 5.1 模型连接工具

类似 MCP 的协议把工具、资源和提示模板用统一方式暴露给模型。这样一个 Agent 可以用相近的方式接入：

- 文件系统
- GitHub
- 数据库
- 搜索引擎
- 企业知识库
- 浏览器

但协议统一不等于自动安全。工具仍然需要最小权限、参数校验、日志、敏感信息过滤和人工审批。

### 5.2 Agent 之间互相调用

多 Agent 系统需要解决发现能力、传递任务、返回结果、身份认证和权限问题。未来可能出现更多“Agent 调用 Agent”的场景，例如研发 Agent 调用测试 Agent，办公 Agent 调用数据分析 Agent。

现阶段这方面仍比单 Agent 工具调用更复杂。很多“多 Agent”产品实际上是一个调度器顺序调用多个模型角色，并不代表已经形成稳定的自治组织。

## 六、多模态和计算机操作

模型输入输出正在从纯文本扩展到：

- 图片
- PDF 和扫描文档
- 音频和语音
- 视频
- 屏幕截图
- 浏览器和桌面界面

这使 AI 能够处理以前必须人工转录的任务，例如从截图定位 UI 问题、从会议录音生成纪要、理解复杂表格或操作网页。

但“能看懂屏幕”与“能可靠操作电脑”是两回事。真实环境中的按钮变化、登录验证、权限弹窗和不可逆操作都会导致失败。因此计算机操作 Agent 应该优先运行在沙箱中，并对支付、删除、发布、发送消息等动作增加确认。

## 七、小模型、本地模型和推理成本

模型能力提升的同时，部署成本也在下降。常见技术路线包括：

- 模型蒸馏
- 量化
- 稀疏化和混合专家
- KV Cache 优化
- 投机解码
- 更高效的推理引擎
- 针对单一任务训练的小模型

这会形成分层架构：

```text
本地小模型：分类、提取、隐私数据预处理、简单补全
云端强模型：复杂推理、代码重构、长流程规划
专用模型：语音、视觉、OCR、Embedding、排序
```

对个人开发者而言，不是所有任务都需要最强模型。把简单任务路由到便宜模型，通常比盲目使用最大模型更实用。

## 八、开源模型和模型组合

开源或开放权重模型让企业和个人可以在本地或私有服务器运行模型，也便于针对特定领域做微调、蒸馏和部署。

实际选择往往不是“只选一个模型”，而是：

```text
通用模型 + 代码模型 + 视觉模型 + Embedding 模型
        + 路由器 + 缓存 + 评测系统
```

开源模型的优势是可控、可私有部署、可定制；代价是需要自己解决硬件、推理速度、升级、监控和安全问题。对个人研发工程师，直接使用成熟托管服务通常维护成本更低；对有隐私、规模或定制需求的团队，本地模型价值更高。

## 九、数据、评测和可靠性变得更重要

模型基准分数提升，不代表它在你的项目中一定可靠。企业落地正在从“看演示效果”转向建立自己的评测集：

- 真实历史任务
- 典型代码变更
- 常见错误输入
- 安全和权限场景
- 成功率、耗时和成本
- 人工返工量

一个实用的 Agent 评测可以记录：

```text
任务是否完成
输出是否正确
修改是否通过测试
调用了哪些工具
花费了多少 Token 和时间
是否产生越权或危险操作
```

这说明 AI 工程会越来越像传统软件工程：需要测试、日志、版本管理、回归检查和发布流程。

## 十、机器人和物理世界

语言、视觉和动作模型正在被用于机器人、自动驾驶、仓储、工业控制等方向。相比处理网页和代码，物理世界有更高的延迟、成本和安全要求。

该方向的关键问题包括：

- 感知是否准确
- 动作是否稳定
- 是否能处理长尾情况
- 错误是否会造成人身或财产损失
- 是否需要人工接管

机器人是很重要的长期方向，但对普通软件研发工程师来说，短期内影响不如代码 Agent、工具协议、多模态和推理成本直接。

## 十一、哪些是已实用，哪些仍偏宣传

### 已经比较实用

- 代码解释、补全、重构和测试辅助
- 文档总结、信息抽取和格式转换
- 多模态文件理解
- 结构化数据分析
- 搜索、检索和知识库问答
- 有边界的工具调用
- 基于定时任务的报告和监控

### 需要谨慎验证

- 完全自主的软件项目交付
- 长时间无人监督的复杂 Agent
- 自动操作生产环境
- 自动处理支付、删除和发布等不可逆操作
- 多 Agent 自主协商后产生可靠结果
- 只依靠模型自身记忆保证事实正确

### 仍然容易被营销夸大的说法

- “完全替代工程师”
- “无限自主、永不出错”
- “多 Agent 数量越多越聪明”
- “接入工具后自然就安全”
- “基准测试第一就适合所有项目”

## 十二、对研发工程师的实际影响

### 12.1 当前最值得掌握

1. 使用代码 Agent 完成真实项目任务，而不是只问代码片段。
2. 学会写清楚需求、约束、验收标准和测试条件。
3. 能阅读和审查 AI 生成的代码。
4. 掌握 Git、测试、日志、调试和自动化脚本。
5. 了解 MCP、API、权限和沙箱的基本原理。
6. 为常见任务建立可重复的提示词、Skills 和项目规则。
7. 建立自己的任务评测，而不是只凭主观感觉判断模型好坏。

### 12.2 对当前项目的适用方式

可以按下面的分工使用工具：

```text
Codex：读取项目、修改代码、运行测试、调试和审查
WorkBuddy：正式报告、PPT、表格和办公材料
Hermes/OpenClaw：定时任务、消息入口、服务器巡检和后台自动化
```

如果主要工作是在本地项目中研发，先把 Codex 的项目上下文、测试命令、文档规范和工具接入配置好，通常比部署一个常驻通用 Agent 更有收益。

## 十三、一个更准确的未来判断

未来几年更可能出现的不是“一个万能 AI 取代所有软件”，而是：

```text
多个专业模型
  + 多种工具
  + Agent 工作流
  + 企业数据和权限
  + 软件工程式的评测与审计
```

AI 会逐渐成为软件系统中的一个可调用执行层。真正有竞争力的产品，不只是模型回答得好，还要能把任务安全、低成本、可追踪地完成。

## 十五、关键结论

1. AI 的主线正在从“生成内容”转向“在环境中执行任务”。
2. 推理模型提高了复杂任务能力，但不能替代外部验证。
3. 代码 Agent 是目前对研发工程师最直接、最成熟的应用方向之一。
4. MCP、Agent 互操作、权限和审计会成为 AI 软件基础设施的重要部分。
5. 多模态让 AI 能处理图片、音频、视频、文档和屏幕，但真实操作仍需要沙箱和人工确认。
6. 小模型、本地模型和模型路由会降低成本并改善隐私。
7. AI 工程最终仍然需要测试、监控、版本管理、权限控制和回归验证。
