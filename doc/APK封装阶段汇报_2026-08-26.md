## 二、基础概念说明

### 1. APK 是什么

APK 是 **Android Package** 的缩写，中文通常称为 Android 应用程序包。它是 Android 手机安装应用时使用的文件格式，文件后缀为 `.apk`。

可以把 APK 理解为 Android 世界里的“应用安装包”。它通常包含：

- 应用代码；
- 页面资源和图片；
- 应用名称、图标和版本号；
- Android 权限声明；
- 签名信息；
- 需要打包进应用的其他资源。

用户点击 APK 安装后，Android 系统会读取其中的信息，将应用注册到系统中，并在桌面生成应用入口。

本项目生成的是 `app-debug.apk`。其中 `debug` 表示使用调试签名，适合测试安装；正式发布时通常要生成经过正式签名的 Release APK 或 AAB。

### 2. Android 系统与 Android SDK

Android 是运行在手机上的操作系统。小米、华为、三星等手机都可以运行 Android，但厂商会在 Android 基础上增加自己的系统界面和功能。

Android SDK 是 **Android Software Development Kit** 的缩写，中文是 Android 软件开发工具包。它不是手机上的业务软件，而是电脑上用来开发和编译 Android 应用的一组工具，主要包括：

- Android SDK Platform：某个 Android 系统版本的 API；
- Android SDK Build-Tools：把代码和资源打包成 APK 的工具；
- Platform-Tools：包含 `adb`，用于连接手机、安装 APK 和调试；
- Android Emulator：Android 模拟器；
- SDK Manager：管理不同 Android 版本和工具的程序。

Android Studio 是官方开发环境。它包含代码编辑器、项目管理、Gradle 构建支持、模拟器入口和 SDK 管理界面，所以本项目安装的是 Android Studio，而不仅是单独下载 SDK。

### 3. JDK 与 Android SDK 的区别

JDK 是 **Java Development Kit** 的缩写，主要提供 Java 编译器和 Java 运行环境。Android 工程中的部分原生代码和 Gradle 构建过程需要 JDK。

两者职责不同：

```text
JDK         → 提供 Java 编译和运行环境
Android SDK → 提供 Android 平台、打包工具和 adb
Gradle      → 按 Android 工程配置组织并执行构建
```

本机可以同时安装 Java 8、JDK 17 和 JDK 21。它们互不冲突，构建 Android APK 时通过 `JAVA_HOME` 指定 JDK 21；其他旧项目仍然可以继续使用 Java 8。

### 4. WebView 是什么

WebView 不是移动端前端，也不是一套新的页面代码。WebView 是 Android 提供的网页显示组件，可以理解为“嵌在 Android 应用里面的浏览器页面区域”。现代 Android WebView 通常使用 Chromium 的网页渲染能力。

普通浏览器的关系是：

```text
Chrome 浏览器 → 打开网页
```

本项目的关系是：

```text
Android APK → 内置 WebView → 打开网页
```

WebView 可以加载 HTML、CSS、JavaScript，因此能够运行 React、Vue 等网页前端。它负责网页的加载和显示，但页面内容和业务逻辑仍然由 React 前端代码决定。

### 5. Capacitor 是什么

Capacitor 是一个把 Web 前端封装成 Android/iOS 应用的工具。它会生成一个原生 Android 工程，并在里面放置 WebView。

Capacitor 的作用包括：

- 生成 Android 项目目录；
- 提供应用名称、包名、图标和启动页配置；
- 将网页前端放入或连接到 WebView；
- 提供 JavaScript 调用 Android 原生能力的桥接机制；
- 让网页项目可以使用部分相机、文件、通知等原生插件。

本项目目前只使用了 Capacitor 的基础外壳功能，还没有接入相机、推送等复杂原生插件。

### 6. React 前端是什么

React 前端是运行在网页环境中的用户界面代码，负责：

- 页面布局；
- 菜单和路由；
- 登录表单；
- 股票表格和图表；
- 用户点击、输入和页面状态；
- 调用后端 API 并显示结果。

React 代码经过 Vite 构建后，会变成浏览器能够加载的 HTML、CSS 和 JavaScript 文件。浏览器可以运行这些文件，Android WebView 也可以运行这些文件。

因此，React 前端不等于 APK。React 前端是“页面和交互”，APK 是“Android 安装包和运行容器”。

### 7. FastAPI 后端是什么

FastAPI 是 Python 后端框架。本项目的 FastAPI 后端负责真正的服务器业务，包括登录鉴权、股票数据、数据库读写、AI 接口和后台任务。

React 前端不会直接访问数据库，而是通过 HTTP 请求访问 FastAPI：

```text
React / WebView
       ↓  HTTP 请求
FastAPI API
       ↓
数据库、缓存和后台任务
```

### 8. Nginx 是什么

Nginx 是部署在服务器上的 Web 服务器和反向代理。当前项目中它有两个主要作用：

1. 返回 React 构建后的静态网页文件；
2. 把 `/api/` 请求转发给 FastAPI。

所以 APK 不需要知道 FastAPI 容器的内部地址，只需要访问公网服务器的 Nginx 地址。

### 9. 当前 APK 不是离线应用

本项目配置了远程地址：

```ts
server: {
  url: "http://124.222.169.60/",
}
```

这表示 APK 启动后，WebView 会从服务器加载网页。当前 APK 更像是一个带有独立图标和窗口的项目入口，而不是把全部网页和后端都装进手机。

服务器无法访问时，APK 也无法正常显示业务页面。只有把网页资源真正打包到 APK，并另外设计本地数据和接口方案，才可能实现离线运行；本项目当前没有采用这种模式。

### 10. 几个概念的关系

```text
React 前端
  = 页面、交互、图表和浏览器端业务逻辑

WebView
  = Android 中显示和运行网页的组件

Capacitor
  = 把 WebView 和网页项目包装成 Android 工程的工具

APK
  = Android 系统可以安装的应用程序包

Android SDK
  = 编译、打包、安装和调试 APK 所需的工具集合

FastAPI
  = 服务器端 API 和业务逻辑

Nginx
  = 对外提供网页，并把 API 请求转发给 FastAPI
```

## 三、原项目的整体架构

当前项目本身是前后端分离、由 Nginx 统一对外提供访问入口的架构：

```text
用户浏览器 / Android APK
          │
          │ HTTP 请求
          ▼
公网服务器：124.222.169.60:80
          │
          ▼
       Nginx
       ├── /             → React/Vite 构建后的静态前端
       ├── /assets/      → 前端静态资源
       ├── /api/         → 反向代理到 FastAPI
       └── /health      → 反向代理到 FastAPI
                              │
                              ▼
                         FastAPI API
                              │
                              ▼
                       数据库 / 缓存 / Worker / 外部数据源
```

### 1. 前端

前端位于 `frontend/`，主要技术栈为：

- React 18
- TypeScript
- Vite
- React Router
- Ant Design
- Axios
- TanStack Query
- ECharts

前端 API 客户端使用相对路径，例如 `/api/...`。这意味着浏览器或 APK 访问哪个服务器，API 就跟随同一个服务器地址，不需要在每个接口中单独写公网 IP。

### 2. 后端

后端位于 `backend/`，使用 FastAPI 提供接口。后端负责：

- 用户登录和 JWT 鉴权；
- 访客账号和管理员账号；
- 股票、ETF、债券、板块等数据接口；
- 帖子、摘要、AI 相关接口；
- 数据库访问、缓存和后台任务。

APK 不直接连接数据库，也不应直接暴露数据库端口。APK 只访问 Nginx 暴露的网页和 API 入口。

## 四、APK 是怎样套出来的

本次使用的是 Capacitor。可以把它理解为：

```text
现有 React 网页
       │
       ▼
Capacitor Android 外壳
       │
       ▼
Android APK
```

APK 内部的核心 Activity 是一个继承自 Capacitor `BridgeActivity` 的 Android Activity：

```java
public class MainActivity extends BridgeActivity {}
```

它本身没有重新实现业务页面，而是启动 Capacitor WebView。WebView 再访问配置中的网页地址。

本项目的核心配置位于 `frontend/capacitor.config.ts`：

```ts
const serverUrl = process.env.CAP_SERVER_URL || "http://124.222.169.60/";

const config: CapacitorConfig = {
  appId: "com.xueqiu.insight",
  appName: "雪球看板",
  webDir: "dist",
  server: {
    url: serverUrl,
    cleartext: true,
    androidScheme: "http",
  },
};
```

其中：

- `appId` 是 Android 应用包名；
- `appName` 是应用名称；
- `webDir` 是 Capacitor 默认使用的前端构建目录；
- `server.url` 指定 APK 启动后访问的远程网页；
- `cleartext: true` 允许当前测试阶段使用 HTTP；
- `androidScheme: "http"` 与当前公网 HTTP 地址匹配。

由于当前配置了 `server.url`，这个 APK 的主要运行模式是“远程网页模式”，不是把网页完整打包进 APK 后离线运行。

## 五、为什么前端不需要重写

现有前端已经具备移动端适配：

- 使用响应式布局；
- 小屏幕使用底部 Tab 导航；
- 选股结果在移动端使用卡片布局；
- 登录页和管理页已考虑窄屏显示；
- 项目已有 `manifest.json` 和 Service Worker，具备 PWA 基础。

因此本阶段只增加 Android 容器，不重新制作页面。网页端和 APK 使用同一套 React 代码：

```text
React 源码
   ├── 浏览器访问：由 Nginx 返回 dist
   └── APK 访问：由 Capacitor WebView 打开公网网页
```

后端接口也不需要重写，因为 APK 内的网页仍然请求相对路径：

```text
/api/overview
/api/stock/quote
/api/notes/...
```

这些请求先到公网服务器的 Nginx，再由 Nginx 转发给 FastAPI。

## 七、APK 的构建流程

### 1. 构建网页前端

```powershell
cd frontend
npm run build
```

该命令执行 TypeScript 检查和 Vite 生产构建，输出到 `frontend/dist/`。

### 2. 同步 Capacitor 工程

```powershell
$env:CAP_SERVER_URL = "http://124.222.169.60/"
npm run cap:sync
```

该命令会：

1. 先构建 React 前端；
2. 将 Capacitor 配置写入 Android 工程；
3. 更新 Android 依赖和插件；
4. 同步 Web 资源和原生工程状态。

### 3. 编译 Debug APK

```powershell
$env:JAVA_HOME = "C:\Program Files\Microsoft\jdk-21.0.12.101-hotspot"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
.\android\gradlew.bat -p android assembleDebug
```

最终文件为：

```text
frontend/android/app/build/outputs/apk/debug/app-debug.apk
```

本阶段已实际编译成功，生成的 APK 大小约为 25 MB。

## 八、代码更新时是否需要重新安装 APK

当前是远程网页模式，因此更新分为两类：


| 修改位置                   | 是否需要重新安装 APK                         |
| -------------------------- | -------------------------------------------- |
| FastAPI 后端代码           | 通常不需要                                   |
| 数据库内容、缓存、后台任务 | 不需要                                       |
| 服务器上的 React 前端代码  | 通常不需要，重新部署前端即可                 |
| APK 包名、图标、启动页     | 需要重新构建 APK                             |
| Android 原生权限或原生插件 | 需要重新构建 APK                             |
| 服务器公网 IP 改变         | 需要重新同步并构建，除非改为域名或可配置地址 |

典型的前端更新流程是：

```text
修改 React 代码
    ↓
npm run build
    ↓
重新部署 frontend/dist
    ↓
用户重新打开或刷新 APK
```

所以当前方案的主要优点是：业务功能更新大多数不需要让用户重新安装 APK。

## 九、当前方案的运行限制

### 1. 依赖服务器网络

APK 不是离线应用。服务器不可访问时，APK 也无法正常显示业务页面。

### 2. 当前使用 HTTP

目前地址是：

```text
http://124.222.169.60/
```

这适合开发测试，但正式公开使用建议改为 HTTPS。HTTPS 通常应使用域名和有效证书，避免：

- 登录 Token 被窃取；
- 用户数据被中间人读取或篡改；
- Android 或网络环境拦截明文流量；
- 后续应用商店审核不通过。

正式 HTTPS 化后，需要同步调整：

- `capacitor.config.ts` 中的 `server.url`；
- `cleartext` 配置；
- Nginx 的 443 和证书配置；
- 服务器防火墙和安全组规则。

### 3. 当前是 Debug APK

当前生成的是 `app-debug.apk`，使用调试签名，适合自己或测试用户安装。正式发布需要：

- 配置正式应用签名；
- 设置版本号和版本名称；
- 构建 Release APK 或 AAB；
- 妥善保存 keystore；
- 根据发布渠道处理隐私政策、应用备案和平台审核要求。

## 十、服务器安全边界

建议公网只开放 Nginx 需要的端口：

```text
80   HTTP（当前测试）
443  HTTPS（正式推荐）
```

不建议直接开放：

- 数据库端口；
- Redis 端口；
- FastAPI 内部端口；
- Worker 或管理服务端口。

APK 的安全不能依赖“用户看不到接口”。前端和 APK 都属于客户端，真正的权限控制必须继续放在 FastAPI 后端，通过 JWT、权限检查、限流和输入校验保护接口。

7. 再考虑应用商店发布或面向公众运营。

## 十二、最终架构总结

本项目最终形成的是“服务器业务系统 + Android WebView 外壳”架构：

```text
                 ┌─────────────────────────┐
                 │ Android APK             │
                 │ Capacitor + WebView     │
                 └───────────┬─────────────┘
                             │
                 HTTP/HTTPS  │ 访问公网网页
                             ▼
                 ┌─────────────────────────┐
                 │ Nginx                   │
                 │ 静态前端 + API 反向代理  │
                 └───────┬─────────┬───────┘
                         │         │
                 静态文件 │         │ /api
                         ▼         ▼
                 ┌───────────┐  ┌───────────┐
                 │ React/Vite│  │ FastAPI   │
                 │ 前端      │  │ 后端      │
                 └───────────┘  └─────┬─────┘
                                      │
                                      ▼
                            数据库 / 缓存 / Worker
```

这个方案最大限度复用了现有项目代码，APK 只是新的访问入口。浏览器访问和 Android APK 访问的是同一套前端和后端服务，后续维护成本相对较低。
