## 四、当前已知限制

- Docker 容器重建前不会自动带入新增 Alembic 文件；涉及迁移的代码更新后需要重新 build/up 并执行 `alembic upgrade head`。
- 转债正股映射和发行条款仍未完全覆盖。
- 历史回补已有失败清单和“只重试失败标的”入口，但还需要实际跑一轮失败清单，确认所有失败原因都能正确归档和清除。
- 分时接口依赖东方财富历史分钟数据；周末、节假日、停牌日和接口限流时可能返回空数据或错误，需要前端明确提示。
- 周线/月线当前是请求时由日线聚合，数据量增大后应增加周期缓存，避免重复计算。
- 前端构建仍有部分大 chunk 警告，暂不影响功能使用。
- 30 天免登录 token 保存在浏览器 `localStorage`；适合当前内部项目，公开部署前应评估 XSS 风险和更安全的 HttpOnly Cookie 方案。

## 二、大盘周线/月线

看板首页原来只请求大盘日线。本次增加“日线 / 周线 / 月线”切换，接口支持：

```text
/api/index/kline?code=sh000001&period=day
/api/index/kline?code=sh000001&period=week
/api/index/kline?code=sh000001&period=month
```

后端从新浪获取指数日线，再按 ISO 周或自然月聚合：

- 开盘价取周期第一根日线；
- 最高价取周期内最高价；
- 最低价取周期内最低价；
- 收盘价取周期最后一个交易日；
- 成交量为周期内日成交量之和。

聚合后重新计算 MA5、MA10、MA20、MACD、KDJ 和买卖信号，避免直接复用日线指标。实时行情只合并到日线，避免把一天的数据误显示为整周或整月。

## 三、APK 顶部按钮修复

### 问题

小米 Android 的 WebView 在部分情况下采用 edge-to-edge 显示，网页 Header 进入状态栏区域，导致标题、时间、电量和用户按钮重叠，用户按钮难以点击。

### 修复

前端检测 Capacitor 原生环境，添加 `capacitor-app` 标记，并仅对 APK 页面增加顶部安全区：

```css
.capacitor-app .app-header {
  padding-top: 28px;
  min-height: 92px;
}
```

普通浏览器不会添加该标记，因此不影响桌面网页布局。修复后 Header 会避开 Android 状态栏，用户菜单可以正常点击。

## 四、首屏启动加载界面

APK 是远程 WebView，启动时需要建立网络、获取 HTML、加载 JavaScript、初始化 React 并请求 API，期间可能出现几秒白屏。


React 首屏完成后，`main.tsx` 给启动层添加隐藏类，经过淡出动画后移除。该功能改善等待期间的视觉体验，但不能减少网络和服务器本身的响应时间。APK 不需要重新安装，只需部署最新前端。

## 五、部署中的 502 问题

执行容器更新后，网页接口出现 502。Nginx 日志显示：

```text
connect() failed (111: Connection refused) while connecting to upstream
upstream: http://172.18.0.8:8000/...
```

检查 PostgreSQL 数据仍然存在：

```text
posts        5774
stock_daily  5415260
users        2
```

API 日志也显示已正常启动。因此问题不是数据库丢失，而是 API 容器重建后 Docker 内部 IP 发生变化，frontend 容器中的 Nginx 仍缓存旧 API IP。

重新创建 frontend 容器后恢复：

```bash
cd /data/app/backend
docker compose up -d --force-recreate frontend
```

以后 API 容器重建后建议执行：

```bash
docker compose up -d --build api worker beat
docker compose up -d --force-recreate frontend
```

不要使用 `docker compose down -v`，因为它可能删除 PostgreSQL 和 Redis 数据卷。

## 六、数据库与 Alembic

生产系统当前使用 Docker PostgreSQL，SQLite 仅用于早期迁移和对拍。Git 只同步代码和迁移文件，不会同步 PostgreSQL 数据。

本次确认数据库曾处于 Alembic `0018`，执行：

```bash
docker compose exec api alembic upgrade head
```

后升级到当前项目 head：`0020_backfill_failures`。

需要区分：

- Alembic：升级 PostgreSQL 表结构；
- Docker volume：保存 PostgreSQL 实际数据；
- Git：同步代码和 migration 文件。

涉及数据库结构变更时，部署顺序为：

```bash
git pull origin dev
docker compose up -d --build api worker beat frontend
docker compose exec api alembic upgrade head
docker compose up -d --force-recreate frontend
```
