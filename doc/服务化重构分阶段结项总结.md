## 1. 一句话总结

把一个**单用户本地工具**（Flask + SQLite + 原生 JS + 进程内线程）重构为**可支撑千人并发只读访问的服务化系统**（FastAPI + PostgreSQL + Redis + Celery + PgBouncer + React/AntD，Docker Compose 编排 7 服务），全程**新旧并行 + 逐接口对拍**灰度，零业务算法改写、历史数据零丢失。

## 3. 架构演进（Before → After）

**Before（单机工具）**
```
浏览器 ── Flask(threaded) ── SQLite(单文件)
              │
              └─ 进程内 daemon 线程（采集/同步/总结）+ 内存状态字典 + 轮询
                 （抓取依赖本机可见 Edge + 登录态）
```

**After（服务化）**
```
千人并发读者 ─▶ Nginx(前端 SPA + 同源反代) ─▶ FastAPI(可多实例)
                                              ├─ 异步会话 → 轻量读
                                              └─ threadpool → 重计算(读预计算表)
                        Redis(缓存/broker/限流)  ◀────┤
                        PostgreSQL ◀─ PgBouncer ◀────┘
                              ▲
        Celery Workers ───────┤   （default/llm 容器化；browser 队列在 Windows 宿主，真实 Edge）
        Celery Beat（定时）────┘
```

核心判断：并发压力在**读侧**，采集侧是**单节点后台管线**。因此主线是"异步读 + 重缓存 + 预计算 + 队列解耦"，而非"把抓取扩到千倍"。

## 4. 分阶段总结

### Phase 1 · 后端地基与数据层
- **目标**：立起 FastAPI + Postgres 骨架，迁移全量历史，跑通全部只读接口。
- **交付**：pydantic-settings 配置、异步 SQLAlchemy(asyncpg) + 重计算同步引擎、11 张表 + Alembic、SQLite→PG 迁移与校验脚本、14 个公开只读接口、Redis 缓存（dataver 版本号失效）、容器化。
- **验收**：迁移 520 万行/68s + 校验全绿；新旧对拍 16/16。
- **关键决策**：轻量读走异步、重计算（选股/K线，逐字移植）走 threadpool+同步会话；读接口返回原生 dict 以保证与旧 Flask 逐字节一致。

### Phase 2 · 分布式队列与后台任务
- **目标**：后台任务与 Web 解耦，状态可持久化观测，激活管理员写接口。
- **交付**：Celery+Redis 9 任务／3 队列（default 容器化：快照/财务/板块；llm：总结；**browser 宿主专用**：抓取/回补）；`job_runs` 表 + 状态接口取代内存字典轮询；Celery beat 取代内置定时线程（读 `schedules` 表）；同步完成后失效缓存；管理员写接口全部实装。
- **验收**：容器化端到端——触发同步→worker 拉取写库→job_runs 记 done→缓存版本递增；schedule/分组 CRUD、beat tick 均通过。
- **关键决策**：浏览器任务无法容器化 → 专用 `QUEUE_BROWSER` 由 Windows 宿主 worker 消费；触发接口**预建 running 行再入队**，消除状态轮询竞态。

### Phase 3 · 管理员鉴权与限流
- **目标**：确立"公开只读 + 管理员后台"的安全边界。
- **交付**：`admins` 表（migration 0002）+ bcrypt + PyJWT；登录/`me` 接口 + `require_admin` 守卫；启动引导管理员 / `create_admin.py`；slowapi + **Redis 存储**限流（多实例共享）。
- **验收**：无/坏 token→401、公开→200、错误密码→401、正确登录→JWT、登录超频→429，全通。

### Phase 4 · 前端重写
- **目标**：以大厂中后台栈替换原生 JS 页面。
- **交付**：React + Vite + TS + Ant Design + TanStack Query + ECharts；6 页面（看板/帖子流/AI总结/选股/个股详情/管理后台）；JWT 存 localStorage + axios 拦截器 + 路由守卫；Nginx 多阶段构建、**同源反代 `/api`**（前端免 CORS）、SPA history 回退。
- **验收**：`npm run build` 类型检查+构建通过；容器化 nginx 出 SPA、深路由回退 200、`/api` GET/POST/带 JWT 全通。

### Phase 5 · 性能硬化
- **目标**：消除选股全表扫描，补齐可观测性/连接池/备份/CI。
- **交付**：**预计算指标表 `stock_indicator`**（migration 0003，快照/回补后自动重算，未就绪自动回退现算）；`/ready` + `/metrics`（Prometheus）；PgBouncer 事务池（asyncpg `statement_cache_size=0`）；`backup.sh`（pg_dump）；GitHub Actions CI；前端 vendor code-split。
- **验收**：快路径与现算**结果集与顺序完全一致**、15~25× 提速；`/ready`/`/metrics` 正常；经 PgBouncer 查询通。

## 5. 关键技术亮点

1. **忠实移植 + 对拍验收**：`repositories/sync_data.py` 是旧 `db.py` 的同步近似复刻，`services/*` 逐字移植自 `stock.py`；以旧系统为黄金基准做逐接口 JSON 对拍，作为"零行为漂移"的验收闸门。
2. **异步/同步分界**：高并发轻量读用 asyncpg 异步；CPU 密集且逐字移植的计算跑 threadpool + 独立小同步池 —— 兼顾并发与移植保真。
3. **dataver 缓存失效**：缓存 key 内嵌全局数据版本号，同步后一次 `INCR` 即整体失效，热路径无 `KEYS/SCAN`。
4. **预计算消除全表扫描**：把"每请求 5500×90 现算"降为"每次数据更新算一次"，选股请求变为一次索引读，是抗读并发的关键。
5. **浏览器任务隔离**：真实 Edge 抓取无法容器化 → 独立队列 + 宿主 worker，其余全部容器化，架构不被单点拖累。

## 6. 踩坑与经验（Lessons Learned）

| 坑 | 现象 | 处置 |
|---|---|---|
| 本机端口占用 | 5432/6379/8000 被另一套栈占用 | remap 到 5433/6380/8088（+ pgbouncer 6432、前端 8090） |
| Windows GBK 控制台 | 打印 emoji/中文 `UnicodeEncodeError` | 脚本统一 `reconfigure(utf-8)`；alembic.ini 保持 ASCII |
| 跨库排序差异 | 中文名在 PG/SQLite collation 下顺序不同 | 内容一致，关键列表显式 `ORDER BY` / 前端排序 |
| `==` 操作符 | SQLite 接受、Postgres 报错 | 渲染 SQL 时 `==`→`=` |
| slowapi headers | `@limiter.limit` + headers 要求端点声明 `response` | `headers_enabled=False`（限流照常，超限仍 429） |
| tsconfig composite | 引用工程不能 `noEmit` | 去掉 `noEmit`，`types:["node"]` |
| PgBouncer 镜像 | edoburu 监听容器 5432、scram 丢连接 | 映射 `6432:5432` + `AUTH_TYPE=plain` + asyncpg `statement_cache_size=0` |
| docker.io 拉镜像 | 基础镜像偶发 auth 超时 | 重试即可（本机网络对 docker.io 不稳定） |

## 7. 质量与验证汇总

- **迁移校验**：逐表计数 + `MAX(created_at)`/`SUM(like_count)`/`COUNT(DISTINCT code)` 等聚合抽查。
- **接口对拍**：`parity_check.py` 自发现参数，固定矩阵逐接口比对新旧 JSON（浮点容差 + 无序列表集合比较）。
- **端到端**：Phase 2 队列链路、Phase 3 鉴权/限流、Phase 4 前端经 nginx 全链路、Phase 5 预计算等值性，均在容器环境实测通过。
