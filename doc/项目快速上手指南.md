## 一、项目是什么？

**雪球大 V 帖子抓取 + AI 总结 + A 股行情/财务/选股系统**

- **核心功能**：
  - 抓取雪球大 V 帖子，AI 生成每日/每周总结
  - 提供 A 股实时行情、K 线图表、财务数据
  - 智能选股（均线金叉、MACD、KDJ、财务指标等）
  - 模拟盘交易、自选股管理
  - AI 助手「菲比」（Live2D + 语音交互）

- **技术架构**：前后端分离，Docker Compose 7 服务栈
- **当前分支**：`dev`（主开发分支），`release_v1`（旧单机版已废弃）

## 二、技术栈速览

### 后端（FastAPI）
- **语言**: Python 3.12
- **框架**: FastAPI + SQLAlchemy 2.0（异步）
- **数据库**: PostgreSQL + PgBouncer（连接池）
- **缓存**: Redis（dataver 版本失效机制）
- **异步任务**: Celery（3 队列：default / llm / browser）
- **数据源**: 新浪财经、东方财富、雪球（需真实浏览器登录）

### 前端（React）
- **框架**: React 18 + TypeScript + Vite
- **UI 库**: Ant Design 5
- **状态管理**: TanStack Query（服务端状态）+ Zustand（客户端状态）
- **图表**: ECharts 5
- **特色**: Live2D 看板娘「菲比」+ 触屏手势优化

### 基础设施
- **容器化**: Docker Compose（7 服务）
- **反向代理**: Nginx（多阶段构建 + 同源 `/api` 转发）
- **迁移工具**: Alembic
- **部署**: 云服务器 Ubuntu 22.04

## 三、快速启动（本地开发）

### 3.1 环境要求
- Docker Desktop（Windows/Mac）或 Docker Engine（Linux）
- Git
- （可选）Python 3.12 + pip（用于宿主 Celery browser worker）

### 3.2 一键启动

```bash
# 1. 克隆项目
git clone https://github.com/ChineseCz/AiForA.git
cd AiForA
git checkout dev

# 2. 启动 Docker 栈
cd backend
docker compose up -d

# 3. 首次启动：数据库迁移
docker compose exec api alembic upgrade head

# 4. 浏览器访问
# 前端: http://localhost:8090
# API 文档: http://localhost:8088/docs
```

### 3.3 宿主 Celery Worker（可选，用于雪球抓取）

```bash
# 安装依赖
cd backend
pip install -r requirements-host.txt

# 启动 browser 队列 worker（Windows 需真实 Edge）
celery -A app.workers.celery_app worker -Q browser --pool=solo
```

## 五、关键概念

### 5.1 异步/同步分界

- **异步会话**（asyncpg）：轻量读接口（`/api/user/me`、`/api/posts/*`）
- **同步会话**（psycopg）：选股/K 线计算（历史逻辑移植，跑 `run_in_threadpool`）

⚠️ **不要在事件循环里直接调用同步会话**

### 5.2 缓存失效机制（dataver）

- Redis key 格式：`cache:{type}:{key}:v{dataver}`
- 数据同步任务结束时 `cache.bump_dataver_sync()`（INCR 版本号）
- 旧版本 key 自动失效，无需逐个删除

### 5.3 预计算指标

- `stock_indicator` 表存储预计算的 MA/MACD/KDJ
- 选股优先读此表（`_fresh_indicators()`），不新鲜才回退现算
- 由 `recompute_indicators` 任务在快照/回补后自动触发

### 5.4 Celery 队列分工

| 队列 | 任务类型 | Worker 位置 |
|------|---------|------------|
| `default` | 快照同步、财务同步、指标计算 | Docker 容器 |
| `llm` | AI 总结、菲比问答 | Docker 容器 |
| `browser` | 雪球抓取、K 线回补、雪球板块同步 | **宿主机**（需真实 Edge） |

### 5.5 K 线前复权

- 新浪 K 线是**不复权价**
- `kline.py` 回补时自动用 `sina.fetch_qfq_factors` + `adjust.compute_qfq` 转前复权
- `save_history_bars` 写入语义是**整行覆盖 OHLC**（不是只补空）

### 5.6 定时任务开关

- Celery beat 的 `schedule` 是启动时静态字典，**不支持运行时暂停**
- 开关统一做成"任务函数第一件事读 `schedules` 表字段，不满足就 return"
- 示例：`tasks/beat.py::scheduler_tick` 读 `schedules.post_crawl_enabled`

## 九、常见问题速查

### Q1: 容器启动失败？
```bash
docker compose logs api  # 查看错误日志
# 常见原因：端口占用、环境变量缺失、数据库未就绪
```

### Q2: API 返回 404？
- 检查路由是否注册：`app/main.py` 的 `include_router`
- 检查容器代码是否最新：**重建容器而不是重启**

### Q3: 前端显示兜底文本？
- 检查 API 返回：浏览器 F12 Network 标签
- 检查 JWT token：`localStorage.getItem('token')`
- 清除缓存：`localStorage.clear()` 后重新登录

### Q4: Celery 任务不执行？
```bash
docker compose logs worker  # 查看 worker 日志
docker compose logs beat    # 查看调度器日志
docker compose exec redis redis-cli  # 查看队列长度
> LLEN celery
```

### Q5: 数据不一致？
- 检查缓存版本：`docker compose exec redis redis-cli GET dataver`
- 手动清缓存：`docker compose exec redis redis-cli FLUSHDB`

## 十、开发规范

### 10.1 代码风格
- Python：PEP 8（`black` 格式化）
- TypeScript：ESLint + Prettier
- 提交信息：`feat/fix/refactor/docs: 描述`

### 10.2 忠实移植原则
- 选股/指标逻辑从 `stock.py` 移植到 `services/`
- **返回 dict 键与旧库一致**（不套 Pydantic），保证对拍
- 改动后必须验证预计算快路径与现算结果一致

### 10.3 禁止事项
- ❌ 不要在异步会话里调用同步 ORM
- ❌ 不要直接删除缓存（用 dataver 失效）
- ❌ 不要在 API 请求里触发全量历史循环
- ❌ 不要在 `beat_schedule` 字典里做开关（用任务体内判断）

## 十二、性能优化要点

1. **选股瓶颈**：预计算指标表（避免每次请求重算 3000 只历史 K 线）
2. **缓存策略**：dataver 版本失效（一次 INCR 全局失效）
3. **连接池**：PgBouncer（事务级池化，`statement_cache_size=0`）
4. **异步 I/O**：FastAPI + asyncpg（轻量读走异步，重计算走 threadpool）
5. **K 线前复权**：回补时一次性计算，不在展示时实时算
