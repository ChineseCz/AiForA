### 🚀 Release v2.0（Phase 1-5，2026-07-09）：服务化重构
**Commits**: `44db4f0` ~ `125f694`  
**核心文档**: `doc/服务化重构分阶段结项总结.md`

#### **架构升级**
- **后端**: Flask → **FastAPI**（异步SQLAlchemy 2.0 + asyncpg）
- **数据库**: SQLite → **PostgreSQL**（520万行迁移，68秒完成）
- **缓存**: 内存 → **Redis**（dataver版本号失效机制）
- **队列**: 进程内线程 → **Celery** 3队列（default/llm容器化，browser宿主）
- **前端**: 原生JS → **React + Vite + TypeScript + Ant Design**
- **容器化**: Docker Compose 7服务编排

#### **性能优化**
- PgBouncer连接池（事务级）
- 预计算指标表（选股15~25× 提速）
- 异步/同步分界（轻量读异步，重计算threadpool）

#### **安全边界**
- 管理员JWT鉴权 + bcrypt密码
- slowapi + Redis限流（公开120/min，登录5/min）
- CORS同源反代

## 十、总结

从单机个人工具到面向千人并发的服务化系统，43天内完成了：

1. **架构升级**：Flask + SQLite → FastAPI + PostgreSQL + Redis + Celery
2. **性能优化**：预计算表（15~25× 提速）+ 异步读 + 连接池
3. **功能丰富**：14个选股策略 + 实时行情 + 3种登录方式 + Live2D助手
4. **体验打磨**：暗色模式 + 移动端适配 + PWA + K线交互重做
5. **安全加固**：10项安全措施 + JWT分层鉴权 + 限流
6. **运营支持**：定时任务开关 + 访客登录开关 + 任务监控

核心设计原则：

- **忠实移植 + 对拍验收**：零行为漂移
- **异步/同步分界**：兼顾并发与移植保真
- **dataver缓存失效**：一次INCR整体失效
- **预计算消除全表扫描**：抗读并发关键
- **浏览器任务隔离**：架构不被单点拖累

下一步优化方向见`doc/访客账号体系后续需求PRD.md`。
